# DailyAlbum official site

`dailyalbumapp.com` and `www.dailyalbumapp.com` now point to the dedicated Alibaba Cloud Function Compute website function in cn-hangzhou. The regional site is live over HTTPS; the app download links remain unpublished until the respective releases are ready.

The site contains two separate, self-contained app destinations:

| URL | App | Website languages |
| --- | --- | --- |
| `/cn/` | 每日专辑, mainland China | Chinese; English at `/en/cn/` |
| `/global/` | DailyAlbum, international | English; Chinese at `/global/zh/` |

Each destination has its own `privacy/`, `support/`, and `sources/` pages. No destination links to or describes the other app. Both apps currently show a truthful pre-release state instead of an unverified App Store link.

The shared root URL is routed by the Function Compute handler using its reported source IP. Explicit `/cn/` and `/global/` routes remain available without cross-linking. Local tests and a mainland-origin live request passed; overseas-origin routing and real-device checks remain to be verified. [Routing plan](routing/geo-routing-plan.md) records the intended behavior and remaining gates.

The website filing shown in the Aliyun console is `鄂ICP备2026052475号-2`, registered for `dailyalbumapp.com` with homepage `www.dailyalbumapp.com`. The exact website number is included in mainland destination footers; international destination pages omit it. The registered content category is `博客/个人空间`. The live landing pages describe the creator's independent work, design choices, and project status; this copy change alone does not establish that the site and planned backend service match the filing. Confirm the actual use with Aliyun before adding a store-download link or backend endpoints. This is separate from the App filing number.

The existing root-level privacy, support, and sources pages remain for legacy links. The new version-scoped information pages are generated by `scripts/build_edition_information_pages.py` from that content and are pre-release candidates; they require final per-app data-flow and legal review before store submission. Landing-page creator credit uses `TSRat`; the personal information handler's legal name remains only in the privacy pages. Product research and design decisions are in `design/`.
